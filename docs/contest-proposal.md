## 问题机理与技术路线

MCAP 附件长度是 UInt64。上游查询在缺少分块索引时，采用默认 64 MiB 预算的整文件回退。外部合并逐条加载记录，附件受默认 16 MiB 普通记录预算约束。录制中夹有大校准包或诊断数据时，这两条路径会触发各自的上限。

补丁按 UInt64 校验记录跨度，分别处理附件描述和载荷。查询沿顶层记录边界跳过附件，提取与写入每段最多传递 64 KiB，沿用原写入器生成 CRC、索引和统计。索引目录可与物理边界核对，异步接口逐段等待写入完成，恢复检查点逐段比对已有输出前缀。选择性扫描保持原有闭区间、物理等时顺序和分页，扫描成本随记录数增长。

## 已复现的结果

官方 Python Writer 生成 67,174,797 字节的无索引录制，含 67,174,400 字节附件。原查询达到整文件回退预算，新增 scan-query 以 15 次请求、270 字节逻辑读取定位附件之后的消息。原外部合并因记录长度失败，补丁输出的三条消息、附件、元数据和索引由官方 Python 读取器核对。JS 与 Node 执行的真实 Wasm 入口均完成附件提取并核对 SHA-256。回归测试通过 JS 311 项、Wasm 265 项，并覆盖取消、损坏 CRC、短读、同名附件与恢复。

## 边界、交付与工作量

ReadSource 在操作期间提供稳定内容。选择性读取与全量数据 CRC 校验分别提供结果。文件宿主在可用 CRC 核对通过后独占发布暂存结果，缺失 CRC 时明确报告未校验，SHA-256 用于复验脚本核对内容。270 字节是源回调逻辑读取量，宿主预读与磁盘 I/O 另有成本。输入为合成录制，异步与文件宿主部署于 Node，核心覆盖 JS/Wasm。
