## 项目基础与增量价值

基于 MIT 许可的 LilaLola67/moonmcap 0.17.5 开发。容器读写、压缩、索引及既有裁剪、合并、恢复能力来自上游。本期新增大附件的有界读取、传输与资源管理能力，处理机器人和传感器录制中夹带标定包、诊断快照时，消息检索、附件提取与裁剪／合并遇到的载荷瓶颈。功能以 MoonBit 库 API、命令行和 JS/Wasm 入口交付，可复用于不同附件内容。

## 问题机理与技术路线

MCAP 附件长度采用 UInt64。上游无索引查询受默认 64 MiB 整文件回退预算限制，外部合并逐条加载记录时受默认 16 MiB 普通记录预算限制。本期保留这些预算，以 UInt64 校验记录跨度，分离描述和载荷。新增 scan-query 按物理记录边界跳过附件，保持闭区间、等时物理顺序和分页；提取、复制与写入采用最多 64 KiB 的载荷窗口，沿用写入器重建 CRC、索引和统计。原 query 行为保留，分块读取遵守既有解压限制。

## 核心功能与可靠性

新增附件索引目录及物理边界核对、名称／媒体类型／时间筛选、有界切片、完整附件校验、同步与异步分段传输、核对已有输出前缀的提取检查点，以及逐文件批量导出。异步传输逐段等待输出完成；导出在发布前持久化意图，恢复时由存储适配器权威核对待发布目标。输入需保持稳定，适配器负责快照原子持久化、输出所有权及暂存清理，多文件发布按逐文件提交。

## 复现实测与验收依据

Foxglove Python Writer 生成 67,174,797 字节的无索引录制，含 67,174,400 字节附件。上游查询触发回退预算，新增扫描以 15 次请求、270 字节逻辑读取定位附件后的消息；上游外部合并触发记录预算，补丁结果由独立 Python 读取器核对消息、附件、元数据与索引。JS 与 Node 托管的真实 Wasm 入口完成提取并核对参考 SHA-256。全库回归通过 JS 311 项、Wasm 265 项，覆盖取消、短读、损坏 CRC、同名附件及恢复。源码、复现命令及[实测记录](evidence/attachment-stream.json)随仓库交付。

## 边界、来源与工作量

运行时核对可用 CRC，缺失时报告未校验；SHA-256 属于复验脚本的独立比较。选择性读取与全文件校验分别提供结果。270 字节为逻辑读取量，64 KiB 为载荷窗口，宿主预读、摘要及分块解压另有成本。输入为合成录制，文件与异步宿主运行于 Node，核心覆盖 JS/Wasm。本期有效 MoonBit 实现新增 3,205 行、删除 40 行、净增 3,165 行，排除上游既有代码、测试、注释、空行、生成文件和其他语言。AI 辅助开发与材料整理，申报人负责理解实现并复现实测。[固定上游与许可](https://github.com/LilaLola67/moonmcap/tree/e99a19f101092c982189d85d9536cf47eb5587c4) · [实现提交](https://github.com/DWS-ai-nb/moonmcap/commit/a7922a006e85971b6319438cad3533ed0bb78539)
